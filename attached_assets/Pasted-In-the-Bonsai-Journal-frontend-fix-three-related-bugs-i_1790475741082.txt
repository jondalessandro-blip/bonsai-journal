In the Bonsai Journal frontend, fix three related bugs in the species suggestion feature on the tree form (src/components/TreeForm.tsx and src/lib/speciesMatcher.ts). None of these need backend or schema changes.

First bug: the call to useListTrees() at the top of TreeForm.tsx currently fetches with no parameters, which means the server only returns the 48 oldest trees in the collection, ordered by when each was added. Any tree added after that 48th one is invisible to the species-suggestion matcher, even though it's a completely normal tree in the collection. Change this call to explicitly request the maximum page size the backend allows, which is 200, so the matcher can see the user's entire realistic collection.

Second bug: curated species suggestions (getSpeciesSuggestions) and the collection-suggestion filter (speciesEntryMatchesQuery) both match the typed query as a substring anywhere inside a name, alias, or scientific name. This causes false positives, like typing "one" matching "Cotoneaster", "Honeysuckle", "Money Tree", and "Bristlecone Pine" just because those words happen to contain the letters o-n-e in the middle. Change the matching so the typed query only matches at the start of a word within the phrase, so "scotch" still matches "Scotch Bonnet" and "pine" still matches "Bristlecone Pine", but "one" no longer matches unrelated words that merely contain those letters somewhere in the middle. Keep it case-insensitive, same as today.

Third bug: matching against the user's own collection currently breaks whenever two or more trees share the exact same species text. getSpeciesSuggestionsFromTrees collapses all trees with the same species into a single entry, and when it does, it uses the shared species text as the label instead of any tree's name, which was a deliberate recent fix for mislabeling. The side effect is that none of those trees' actual Name text is stored anywhere the matcher can search, so typing a tree's name finds no match at all even though the tree genuinely exists in the collection. Restructure this so matching happens against every individual tree's Name and Species text before any grouping happens, and only after finding which trees match the typed query, group the matching trees by species text to decide the display label using the existing rule: if two or more trees in the whole collection share that species, show the species text as the label, otherwise show that one tree's name.

Please don't change the curated species reference data file, the visual layout of the suggestion list, or the recent label-formatting fix that shows the scientific name alone when the common name and scientific name are identical. This is frontend-only.
