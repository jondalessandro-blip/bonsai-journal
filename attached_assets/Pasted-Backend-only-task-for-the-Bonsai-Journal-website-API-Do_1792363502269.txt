Backend only task for the Bonsai Journal website API. Do not touch any frontend files and do not touch or report on the bonsai-mobile app. Work on the dev branch.

Goal: add one new endpoint that completes many scheduled care reminders at once, doing exactly what the single-tree circle shortcut does today, but all in one database transaction.

Step 1, OpenAPI spec first. In lib/api-spec/openapi.yaml add a POST /reminders/complete-bulk operation (named completeRemindersBulk). Request body fields: reminderIds (array of 1 to 200 strings, uuid format), dateMode (either "single" or "scheduled"), date (string in YYYY-MM-DD form, required when dateMode is "single", ignored otherwise), and today (string in YYYY-MM-DD form, required; this is the user's local calendar date sent by the browser, so the server never relies on its own clock or time zone). Response 200 returns completedCount (integer), logs (array of the existing care log schema), rescheduled (array of objects with reminderId and newDueDate), and deletedReminderIds (array of strings). Then run pnpm --filter @workspace/api-spec run codegen. Never hand edit the generated files under lib/api-zod or lib/api-client-react.

Step 2, the route in artifacts/api-server/src/routes/trees.ts, using requireAuth like the neighboring routes, and registered so it does not clash with existing paths. Rules:
Remove duplicate ids from reminderIds first. Inside one transaction, load the reminders joined to trees where the tree belongs to the current user and the reminder is not already completed, locking the rows with for update. If any requested reminder is missing, not owned by the user, or already completed, write nothing and return 404 with a clear message.
The log date for each reminder is body.date when dateMode is "single", or that reminder's own dueDate when dateMode is "scheduled". If any log date is later than body.today, write nothing and return 400 with a clear message (this also means "scheduled" mode rejects tasks that are not due yet).
For each reminder insert a care log with the reminder's treeId, type, the chosen log date, and the reminder's notes carried over unchanged. Then, if the reminder is recurring (recurring is true with an interval value and unit), update that same row's dueDate to the next due date and leave it not completed; otherwise delete the reminder row. This must match what the website circle shortcut does today.
Recurring next due date: add a server-side copy of computeNextDueDate and skipExcludedMonths from artifacts/bonsai-journal/src/lib/care-recurrence.ts, using body.today instead of the machine's current date. Keep the same rule: start from whichever is later, today or the reminder's current due date, add the interval (days, weeks, months or years, with month-end clamping like date-fns addMonths so Jan 31 plus one month is Feb 28), then skip forward month by month while the result falls in an excluded month. Do not add any new package; if date-fns is not already a dependency of the api-server, use plain date arithmetic. Handle the case where all 12 months are excluded by returning 400 and writing nothing.

Step 3, tests in the api-server test suite. Cover at least: one-time reminders complete and are deleted with the right log date and notes; recurring reminders write a log and advance the due date; excluded months are skipped; month-end clamping; "scheduled" mode uses each reminder's own due date; "single" mode uses the given date; a future log date is rejected with nothing written; a reminder owned by another user causes a full rollback with nothing written; an already completed reminder causes a full rollback; duplicate ids are counted once. Add a few tests that feed the same inputs to the server copy and the frontend helper's logic and confirm the dates agree.
